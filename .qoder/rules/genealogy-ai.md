# AI 家谱编辑系统 — 项目硬规则

> 适用范围：`genealogy-ai/`
> 优先级：高于 `AGENTS.md`（由项目负责人指定）。
> 唯一事实来源：`specs/ai-genealogy-spec.md`（以下简称 Spec）。规则与 Spec 冲突时，以 Spec 的验收标准为准，但本文件的门禁与原则不可被实现层绕过。

---

## 0. 工作门禁（不可跳过）

### 门禁 1：先方案，后代码

- 每个工作包先输出：实现方案、涉及文件路径清单、测试与验证方式、预计改动范围。
- 只有项目负责人明确授权后，才能写该工作包的代码。
- Spec 审核通过且负责人明确说 “Run” 之前，禁止创建业务代码、安装依赖、建库、跑迁移。
- 一次授权只覆盖一个工作包；进入下一包必须重新授权。

### 门禁 2：强制完整输出

- 禁止片段、伪代码、骨架、TODO 占位。
- 禁止 “为简洁起见”“其余部分相同”“// 省略” 等省略语。
- 每个文件必须包含完整 import、类型定义、方法体、异常处理、空值与边界判断。
- 多文件时逐文件输出，每个文件开头用 `###` 标注完整相对路径，例如 `### server/src/modules/persons/service.ts`。
- 代码必须能通过 `tsc --noEmit`、ESLint 与对应测试；不得靠“后续补上”过关。

### 门禁 3：最小可运行

每个工作包交付必须同时包含：

1. 实现代码；
2. 迁移脚本（如涉及数据变更）；
3. 可直接运行的测试用例（含失败路径）；
4. 启动/验证步骤与预期结果。

未通过该工作包的最小验证，不得进入下一个工作包。每完成一个工作包，对照 Spec 的验收标准自查，报告“通过 / 未通过”及原因。

### 门禁 4：命令授权

- 涉及 `npm install`、`prisma migrate`、建库、生成种子、启动服务等终端命令时，先输出：完整命令、作用、预计影响（文件/端口/数据）。
- 得到负责人确认后再执行。
- 禁止 `sudo`、禁止全局安装（`npm i -g`）、禁止修改系统配置或沙箱权限。
- 不擅自删除数据、上传目录、数据库文件或用户未提交的改动；破坏性操作必须先确认。

### 门禁 5：范围控制

- 不自行扩展需求，不“顺手”重构无关模块。
- 追加需求只能由负责人主动发起，并先更新 Spec 再实现。
- WBS 的第 1 层与第 2 层条目不得增删改；第 3 层工作包由 Spec 定义，调整需负责人确认。

## 1. 五条不可协商原则（P1–P5）

### P1：AI 只生成建议，不写正式事实

- AI 输出只能进入 `AiDraft`（抽取草稿）或 `Narrative(status=DRAFT)`。
- AI 模块不得直接写 `Person` / `Relation` / `Event` / `Citation`。
- 任何事实写入必须由用户显式确认（接受草稿、确认叙事），并记录 `AuditLog`。
- 不存在“自动接受高置信度草稿”的开关。

### P2：抽取结果必须可验证

- 每条 AI 草稿必须携带非空 `sourceQuote` 与 `0–1` 的 `confidence`。
- `sourceQuote` 必须是来源原文的子串（服务端校验）；不通过则禁止接受，直到人工修正。
- 姓名、日期、地点等事实值必须能在来源引文中找到依据；否则标记 `FIELD_NOT_IN_QUOTE` 并禁止直接接受。
- 不确定字段必须为 `null` / 空，禁止编造祖先、配偶、子女、来源或日期。
- Prompt 中明确禁止补全；服务端用严格 JSON Schema + zod 校验模型输出。

### P3：隐私默认安全

- 无死亡事实的人物默认 `livingStatus=LIVING`；`UNKNOWN` 按在世处理。
- 在世人物默认私有；VIEWER 视角与所有导出/分享一律自动脱敏。
- 调用第三方 AI 前必须经过脱敏网关（去直接标识、占位符替换），并提供“脱敏预览 + 人工确认”。
- 禁止把原始图片、完整姓名、身份证号、电话、邮箱、详细住址直接发给第三方 AI。
- API Key 只存在服务端环境变量，不得进入前端、日志、数据库或导出文件。

### P4：叙事逐句可追溯

- 叙事生成只允许使用“带来源引用的事实包”；无来源字段不进入事实包，并向用户显示“未纳入”的原因。
- 模型只输出 `text + factRefs`；引用由服务端根据 factRefs 解析并附加，模型不能伪造来源。
- 每句事实性描述必须至少绑定一个有效 factRef；不满足则不能确认、不能导出。
- 导出 Markdown/HTML 时保留脚注引用。

### P5：高风险操作必须人工确认并审计

- 合并人物、删除人物、删除关系：必须走审核流程（提交 → 批准/驳回）；管理员自行批准时必须二次确认并填写理由。
- 所有合并/删除/脱敏状态变更均写入不可变 `AuditLog`（before/after 快照）。
- 审计日志只允许追加，不提供修改/删除 API；仅 ADMIN / REVIEWER 可查询。
- 审核通过执行前必须校验 `version`；数据已被他人修改时返回 409，要求重新预览。

## 2. 技术与工程约束

- 技术栈：Node.js 24 + TypeScript + React 18 + Ant Design 5 + React Flow + Express 4 + Prisma + SQLite。禁止引入 Docker、MySQL、Redis、消息队列、微服务。
- 单仓库单 `package.json`；前端 `web/`、后端 `server/`、共享 `shared/`、规格 `specs/`。
- 所有接口统一前缀 `/api/v1`；统一响应 `{ code, message, data }`；错误含稳定错误码与 `requestId`。
- 认证：httpOnly Cookie + JWT；RBAC 四角色：ADMIN / EDITOR / REVIEWER / VIEWER。
- 数据：SQLite 单文件（`data/genealogy.db`），开启 WAL、外键、busy_timeout；上传文件存 `data/uploads/`，文件名随机化，只能经鉴权接口读取。
- 日期：支持部分日期（年/月/日可空）+ 原文 + 精度 + 是否约值；不得把不确定日期伪造成精确日期。
- 行为：人物删除为软删除（`status=DELETED`）；关系/引用按审核结论物理删除并保留审计快照；所有可编辑实体（人物/关系/叙事）写操作带 `version` 乐观锁。
- 性能边界：单人维护 ≤ 10,000 人；树接口默认深度 4、节点上限 2000，超出走分片/懒加载。
- Windows 环境：路径含空格，脚本必须使用相对路径与正确引号；不依赖 Bash 专有行为。

## 3. 安全编码约束

- 所有输入经 zod 校验；禁止拼接 SQL；只有受控的内部常量可进入 `$queryRawUnsafe`。
- 密码 bcrypt（cost ≥ 12）；登录限流；禁用账号立即失效。
- Cookie：`httpOnly`、`sameSite=strict`、生产 `secure`；变更请求校验 Origin + `X-Requested-With`。
- 上传：MIME/扩展名/大小白名单（图片 jpg/png/webp、文本 txt、GEDCOM ged，≤ 10MB）；禁止路径穿越；禁用 MIME 嗅探。
- React 默认转义；叙事 HTML 导出必须显式转义；禁止 `dangerouslySetInnerHTML` 渲染模型输出。
- 日志使用 pino 并 redact：密码、Cookie、Authorization、API Key、完整姓名/日期/联系方式不得出现在普通日志。
- AI Prompt 注入防护：来源文本视为不可信数据，用分隔符包裹；模型无工具调用权限；输出必须过 Schema 与引用校验。
- 错误信息不得泄露堆栈、SQL、文件路径或他人隐私。

## 4. 测试与完成定义（DoD）

每个工作包至少包含：

- 单元测试：纯函数/规则/解析器/脱敏/校验器；
- 集成测试：涉及 API 的包使用 Vitest + Supertest + 临时 SQLite；
- 失败路径：无权限、参数错误、版本冲突、无效引用、空值、越权遮罩；
- 验证步骤：可复制执行的命令与预期输出；
- 报告：对照验收标准列出“通过/未通过”。

全局最终门禁：

- `npm test` 全绿；`npm run build` 成功；`npm start` 可启动；
- 种子数据可重复重置；演示脚本可从零走通；
- 五项原则各有至少一个自动化测试或可复现验收步骤。
